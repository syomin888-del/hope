# ORACLE V5.6 — Portfolio Accuracy

Ставится **поверх установленной V5.5 MAJOR**. База не заменяется. На VPS не требуется промежуточное обновление.

## Причина обновления

Диагностика: 63 исследовательские записи, всего 32 уникальных комбинации «событие–рынок–исход», 31 повтор. Повторы не удаляются, поскольку это результаты разных (или многократно запущенных) моделей. Но общая стратегия не должна учитывать $10 на каждый повтор.

## Изменения

* `v55_paper` остаётся **журналом экспериментов моделей** (для исследования и оценки каждой версии отдельно). Текущие 63 записи не удаляются, прибыль по ним не считается доходностью единой стратегии.
* Новая таблица `v56_portfolio` выбирает **не более одной исследовательской комбинации на одно корневое событие Фонбета**. Ключ `root_id` защищён PRIMARY KEY; повторные запуски не создают дублей.
* Выбор возможен только **ДО начала события** из документированного ранее созданного бумажного эксперимента. Старые, уже начавшиеся матчи не превращаются в новые ставки задним числом. Портфель — подмножество уже сохранённых модельных экспериментов, а не реальное размещение ставок.
* Для согласования нужно ≥2 **разных версий моделей** на одинаковом исходе. Многократная запись одной и той же модели не добавляет голосов. При конкурирующих исходах на один матч оставляется один согласно детерминированному правилу: больше независимых моделей, затем медианный raw EV, затем более низкий коэффициент. Это инженерное правило, НЕ доказанный критерий прибыльности. Правило фиксирует одну запись и позже её не пересматривает.
* `v56_portfolio` ссылается на исходную `v55_paper` по `forecast_id`; после шестичасовой сверки итог, $10 и P&L считаются **только по выбранным строкам**. Не складывать доходность старого журнала и нового портфеля.
* Ужесточена сверка счёта из Sports Open Lab: только источник, который импортирует поле полного времени `score.ft` из OpenFootball, плюс достаточное время после старта. Для NFL счёт из источника без отдельного подтверждённого финального статуса не засчитывается автоматически. `v4_games.final=1` остаётся допустимым подтверждением. Другие источники потребуют отдельного финального подтверждения.
* API `/api/v5/portfolio`, CLI `python oracle_v5.py portfolio --limit 30`, раздел $10 в `/v5` показывает единый портфель вместо сырых экспериментов. CLI `python oracle_v5.py paper` продолжает показывать полные данные моделей. `/api/v5` показывает **оба разных** отчёта: `paper` и `portfolio`.

## Установка

**Терминал Mac** — скачай архив в Downloads и отправь:

```bash
scp ~/Downloads/ORACLE_V5_6_PORTFOLIO.zip root@188.137.232.34:/root/
ssh root@188.137.232.34
```

**Терминал VPS:**

```bash
mkdir -p /root/ORACLE_V5_6_PORTFOLIO
unzip -oq /root/ORACLE_V5_6_PORTFOLIO.zip -d /root/ORACLE_V5_6_PORTFOLIO
python3 /root/ORACLE_V5_6_PORTFOLIO/install.py check
```

Продолжать **только** после `PREFLIGHT OK`:

```bash
python3 /root/ORACLE_V5_6_PORTFOLIO/install.py apply
cd /opt/ORACLE_CORE_v11
# Обновляет прогнозы и выбирает уникальные портфельные сигналы на будущие матчи:
docker compose exec -T sportslab python oracle_v5.py once
# Раздельная бухгалтерия:
docker compose exec -T sportslab python oracle_v5.py portfolio --limit 30
docker compose exec -T sportslab python oracle_v5.py status
# Проверка результатов:
docker compose exec -T sportslab python oracle_v5.py settle
```

Из уже существующих 63 записей **не обязательно** появится 32 сигнала: действуют ограничения по времени матча и независимости моделей. Также некоторые исходы разных рынков относятся к одному матчу и поэтому не будут дублировать ставку.

## Ограничения

* Не гарантирует прибыльность; существующие модели не прошли достаточную независимую калибровку.
* Интерфейс V5 заменяет карточку общего портфеля, но исходные записи модели доступны по CLI и API `/api/v5/paper`.
* Сверка каждые шесть часов уже запланирована релизом V5.5; V5.6 использует её подтверждённые результаты. Если источник не предоставляет финальный статус, расчёт откладывается.
* Без фактически зафиксированной предматчевой цены исторические пустые коэффициенты нельзя восстановить.
* Реальный сервер не подключён к этой среде, поэтому совместимость подтверждается только после `check` и установки.
