# ORACLE V5.5 MAJOR — единый релиз поверх установленной V5.3

**НЕ устанавливать отдельно V5.4.** В этом пакете уже объединены исправления поиска новостей V5.4 и дальнейшая работа с коэффициентами, архивом, исследовательскими ставками и результатами.

## Что меняется

1. `/v5` показывает **только матчи / события, действительно наблюдавшиеся в линии Fonbet**. Активный каталог: предстоящие root-события с активными котировками. История: прежние root-события с фактически наблюдавшимися исходами. Прогнозы, по которым матч не подтверждён в «Фонбете», не выводятся в рабочем списке `/v5`, но остаются в БД для аудита. Другие старые интерфейсы ORACLE намеренно не переписываются.
2. Режим поиска внешних публикаций — **48 событий за полчаса**, теоретический максимум 2 304 запросов на события за 24 часа без простоев и ограничений сервиса. Это **НЕ 2 304 найденные или проверенные статьи**. `events_checked_since_utc_midnight` отражает реальные попытки в текущие сутки по UTC. Период повторной проверки события — 48 часов, чтобы очередь не застревала на одних и тех же 50 матчах. RSS Google News и сетевые ограничения остаются внешними зависимостями; заголовки не считаются проверенными фактами.
3. Новый журнал `v55_paper`: **ровно $10 на каждую отдельно отобранную прогнозную гипотезу**. Исследовательская гипотеза создаётся, когда исход с модельной вероятностью и подтверждённой рыночной ценой сформирован ДО старта, цена не ниже 1.7 и сырое расчетное EV не ниже 0. Независимые модели НЕ переобучаются на коэффициентах. Много исходов одного события являются зависимыми гипотезами и не доказывают стратегию прибыльной. БУКМЕКЕРСКИЕ АККАУНТЫ / РЕАЛЬНЫЕ СТАВКИ НЕ ПОДКЛЮЧАЮТСЯ.
4. Отдельное фоновое задание `v4_v5_paper_settlement_6h` запускает сверку каждые 6 часов. Источники результатов — уже подключённые `sf_matches` с финальным счётом и `v4_games` с `final=1`. Для `sf_matches` дополнительно требуется наблюдение результата позднее начала матча (футбол минимум +2 ч, NFL минимум +4 ч), а для `v4_games` — отметка `final=1`. Отсутствующие / неподтверждённые результаты остаются `PENDING` и будут проверены снова. **V5.5 не гарантирует, что источники действительно доставят счёт в течение 6 часов.**
5. Бухгалтерия: `WIN = $10 × (КФ − 1)`, `LOSS = −$10`, `PUSH = $0`. ROI считается по **разрешённым** экспериментам и их суммарной ставке, а не по ожидающим. Для рынка без однозначной семантики расчёт не проводится.
6. **История цен без подмены.** Для прошедших матчей исходы отображаются из `fb_full_history` с временной меткой до начала матча; если текущая последняя котировка была записана до начала, она также является допустимым наблюдением. `v55_archive_prices` восстанавливает соответствующие исторические коэффициенты для прогнозов только по точному root-id, семантике рынка, порогу тотала и времени `created_at ≤ observed_at < kickoff`. Старая ошибочная привязка не может автоматически дать архивный коэффициент. Ни одна историческая гипотеза не создаёт **новой бумажной ставки задним числом**.
7. Панель `/v5` показывает журнал бумажных ставок и расчёты P&L. Страница старого матча показывает предматчевые коэффициенты, если источник действительно сохранял их до стартового свистка.
8. Исходные модули крипты, акций, старого импорта «Фонбета», вероятностных моделей и базы данных НЕ заменяются; в БД добавляются только таблицы нового учёта и индекс для исторических котировок.

## Установка

На **Mac**, после скачивания архива в Downloads:

```bash
scp ~/Downloads/ORACLE_V5_5_MAJOR.zip root@188.137.232.34:/root/
ssh root@188.137.232.34
```

На **VPS**:

```bash
mkdir -p /root/ORACLE_V5_5_MAJOR
unzip -oq /root/ORACLE_V5_5_MAJOR.zip -d /root/ORACLE_V5_5_MAJOR
python3 /root/ORACLE_V5_5_MAJOR/install.py check
```

Продолжать только при выводе `PREFLIGHT OK`. Если хеш установленного V5.3 изменён вручную, установщик ОТКАЖЕТ без перезаписи. Затем:

```bash
python3 /root/ORACLE_V5_5_MAJOR/install.py apply
cd /opt/ORACLE_CORE_v11
docker compose exec -T sportslab python oracle_v5.py once
docker compose exec -T sportslab python oracle_v5.py settle
docker compose exec -T sportslab python oracle_v5.py doctor
docker compose exec -T sportslab python oracle_v5.py status
```

Пример чтения исторических цен и бумажной бухгалтерии:

```bash
docker compose exec -T sportslab python oracle_v5.py forecasts --history --limit 20
docker compose exec -T sportslab python oracle_v5.py paper --limit 30
docker compose exec -T sportslab python oracle_v5.py events --limit 25
```

Для разового прохода по 48 событиям (может занять несколько минут при медленной сети):

```bash
docker compose exec -T sportslab python oracle_v5.py evidence --batch 48
```

Панель: http://127.0.0.1:8765/v5 через существующий SSH-туннель Mac. API `/api/v5/paper` показывает только бумажные расчёты.

### Что проверять

* `doctor.scheduler`: `v4_v5_paper_settlement_6h`, `v4_v5_evidence_search`, `v4_fonbet_first_party`.
* `status.paper`: `pending`, `resolved`, `net_profit_usd`, `realized_roi_pct`, `last_result_check`.
* `status.research.checked_today_utc`: фактические обработанные события. Целевая расчётная ёмкость `requested_daily_capacity=2304` — НЕ гарантия выполнения.
* `status.predictions.fonbet_matched_visible`: число прогнозных записей, доступных в Fonbet-only списке.
* `status.paper.verified_historical_prices_for_display`: исторические коэффициенты, фактически восстановленные для прогнозных строк.

## Критические ограничения

* Если во время прогноза не был архивирован нужный коэффициент, **проставить точную историческую цену невозможно**. Пустые значения остаются явно неизвестными; будущие/сегодняшние котировки никогда не записываются как вчерашние.
* Из ~331 наблюдавшегося кода факторов только небольшой набор имеет подтверждённую семантику. Все остальные коды видимы в сырых рынках, но не могут автоматически стать проверенной ставкой или результатом.
* 2 304 — **синтетически проверенная пропускная способность планировщика при отсутствии сетевых задержек**, НЕ обещание 2 000 проверенных спортивных досье с составами/травмами. Нет автоматической достоверной информации о настроении каждого спортсмена.
* Финальные результаты будут найдены только для матчей, поддерживаемых подключёнными источниками счёта. Для других событий журнал остаётся в ожидании.
* Работающий сервер не доступен из этой среды: окончательная проверка установки, Docker, сетевого доступа и реальных исходов проводится после обновления на VPS.
* Все результаты PAPER RESEARCH ONLY. Нет доказанного преимущества над рынком и нет совершения реальных ставок.

## Отказоустойчивость

SHA-256 исходных релизов, консистентный online SQLite backup, резервная копия изменяемых файлов, атомарная замена, проверка импортов в `sportslab` и `dashboard`, откат изменённых файлов при неуспешном запуске. После установки новую SQLite миграцию *не откатывают автоматически*, потому что она добавляет только таблицы и индексы и не разрушает прежние данные.
