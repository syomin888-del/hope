# ORACLE V7.0 GLOBAL — прямая установка поверх V5.7

**ВАЖНО:** V5.8 пользователем не установлен, поэтому пакет V7 **включает** V5.8 Research Brain. Предназначен только для исходников V5.7, сверяемых по SHA-256. Нельзя ставить V5.8 до этого пакета. Если `check` не выдаёт `PREFLIGHT OK`, **не запускайте `apply`**.

**Система исследовательская, все ставки бумажные.** Заявления о 3% стабильной дневной прибыли по крипте или 80% выигрыша по спорту не подтверждены и не могут гарантироваться. В старом тесте крипты OOS `mean_net_pct = -0.3763`, `positive_frac = 0.3846` по 2 171 сделкам: это отрицательный результат после моделируемых издержек. Увеличить количество стратегий — не означает исправить отсутствие преимущества.

## Что сделано

1. **Крипта:** отдельный форензический аудит последнего OOS, объяснение блокирующих причин; добавлен независимый журнал исследовательских гипотез с 4 заранее заданными методами (исходный RSI/EMA/объём, BTC-фильтр тренда, перепроданность, пробой). Отбор на отдельной калибровочной части, финальная контрольная часть не используется при выборе. Вход — следующая часовая свеча; выход — через 24 часа; учтены смоделированные комиссии 10 bps и проскальзывание 20 bps за сторону. $10 на сделку и отдельная статистика на виртуальный капитал $1000. Без автоматической торговли. Автоматическое исследование не чаще раза в 24 часа в цикле `once`; все неудачные методы остаются в журнале. Реалистичность исполнения и независимость активов остаются ограничениями.
2. **Спорт:** встроена V5.8 Research Brain — исследовательские статусы по событиям Fonbet, результаты OpenFootball/nflverse/опционально ESPN; модели ELO, FORM и футбольный Poisson; хронологическая проверка на старых матчах, калибровка, OOS. **Это не означает создание достоверной вероятности для всех видов спорта.** Недостаток истории явно маркируется.
3. **Противоречащие ставки:** официальный исследовательский портфель по-прежнему выбирает не более одного исхода на корневой матч благодаря PK(root_id). V7 проверяет этот инвариант в диагностике. Разные, в т.ч. противоречащие гипотезы по одному матчу остаются отдельно как опыты — они НЕ суммируются в доход портфеля.
4. **Ошибки результатов:** старые предупреждения `NO_VERIFIABLE_BOOKMAKER_ROI_FOR_OFFICIAL_SIGNALS` и `NO_SETTLED_PROSPECTIVE_SPORTS_FORECASTS` возникали из-за того, что старый `scorecard` читает `signals`/`sf_forecasts`, а портфель V5.6 живёт в `v56_portfolio` + `v55_paper`. Добавлен отдельный отчёт по действующему журналу; пока нет окончательных исходов, указываются `AWAITING_VERIFIED_PORTFOLIO_SETTLEMENT` и `AWAITING_SETTLEMENT_OF_VERIFIED_FORWARD_PAPER`, а не фиктивная прибыль. Старый официальный журнал остаётся отдельным.
5. **Control Center / ошибки загрузки:** новый `/v7` и `/api/v7` показывают согласованный read-only статус исходников с явными причинами неготовности, вместо имитации «работает». Старый `/command` перенаправляется на `/v7`, прежний центр доступен по `/legacy-command`. Прежняя ошибка `/api/universe` больше не теряется без пояснения: при отказе возвращается тип и сообщение, а V7 не зависит от этого маршрута.
6. **Подключения:** Fonbet и крипта определяются по последним *фактическим* наблюдениям, проверяются свежесть и количество данных. AI: OpenAI, Claude, Gemini — `NOT_CONFIGURED` пока не получены ключи; `CONFIGURED_UNVERIFIED`, когда ключ задан, но не проверен; `WORKING` только после успешного read-only запроса списка моделей (`python oracle_v7.py probe`). Имена и значения ключей никогда не выводятся. Запросы к LLM для платной генерации **НЕ производятся автоматически**. Установка ключей и разрешение на их расход — отдельный шаг.
7. **Статистические модели:** активные методы и проверенные версии показываются по `v58_validation`. CatBoost/XGBoost/PyTorch не выдаются за обученные модели, пока нет проверенных обученных артефактов.

## Установка

С Mac, скачав архив через интерфейс:
```bash
scp ~/Downloads/ORACLE_V7_0_GLOBAL.zip root@188.137.232.34:/root/
ssh root@188.137.232.34
```
На VPS:
```bash
mkdir -p /root/ORACLE_V7_0_GLOBAL
unzip -oq /root/ORACLE_V7_0_GLOBAL.zip -d /root/ORACLE_V7_0_GLOBAL
python3 /root/ORACLE_V7_0_GLOBAL/install.py check
```
**Только если `PREFLIGHT OK`:**
```bash
python3 /root/ORACLE_V7_0_GLOBAL/install.py apply
```
Сигнал успешной установки: `INSTALL OK`. Установщик проверяет контрольные суммы, свободное место, исходные таблицы, создаёт SQLite online backup и резервные копии изменённых исходников, атомарно заменяет файлы, перестраивает `sportslab` и `dashboard`, проверяет импорты и инициирует новые таблицы. При ошибке восстанавливает исходные файлы и перезапускает сервисы; БД не откатывается поверх работающей БД, а полная резервная копия сохранена отдельно.

## Проверка

```bash
cd /opt/ORACLE_CORE_v11
docker compose exec -T sportslab python oracle_v5.py once
docker compose exec -T sportslab python oracle_v7.py status
docker compose exec -T sportslab python oracle_v7.py crypto-audit
docker compose exec -T sportslab python oracle_v5.py brain --limit 30
docker compose exec -T sportslab python oracle_v5.py portfolio --limit 30
docker compose exec -T sportslab python oracle_v5.py doctor
```
**Для явной проверки новых крипто-гипотез** (вычислительная нагрузка зависит от длины базы):
```bash
docker compose exec -T sportslab python oracle_v7.py crypto-backtest --symbols 45 --hours 2500
```
**Для доп. сбора финальных спортивных результатов (неофициальный ESPN):**
```bash
docker compose exec -T sportslab python oracle_v5.py brain-sync --batch 8
```
V7 использует имеющийся фоновый `once`; шестичасовой settlement продолжает работать. В первой синхронизации ESPN может вернуть `PARTIAL` или `ERROR` — это не значит, что каталог Fonbet сломан.

Открой через существующий SSH-туннель `http://127.0.0.1:8765/v7`. Старый интерфейс: `http://127.0.0.1:8765/legacy-command`. История: `/scorecard`, исходный каталог `/v5`.

## Подключение AI (по желанию)

**Не отправляйте ключи в чат и не помещайте их в HTML.** Предоставьте переменные `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` *среде контейнеров Docker Compose*. Просто записать их в `.env` хоста недостаточно, если `compose.yaml` не передаёт их сервису. После конфигурации и перезапуска `sportslab` и `dashboard` выполните:
```bash
docker compose exec -T sportslab python oracle_v7.py probe
docker compose exec -T sportslab python oracle_v7.py integrations
```
Это **только read-only проверка API доступа**, не включение использования токенов для ставок. Публичные справочники OpenAI, Anthropic и Google могут меняться; успешный HTTP 200 подтверждает доступ, но не доказанное качество аналитики.

## Не сделано и почему

- Стабильные 3% прибыли в день по крипте **не доказаны**. Требуются данные исполненных (или строго проспективно зафиксированных) сделок, ликвидность/стаканы/издержки и тест без переобучения на будущем. Алгоритм с отрицательным OOS не превращён в победный подбором гиперпараметров задним числом.
- Достоверные 80% выигрышей в спорте **не доказаны**; у новой версии модели без положительной OOS-проверки не выводятся как готовые сигналы. КФ 1.7 и 80% попаданий теоретически совместимы, но для реального плюса нужны честные котировки и статистическая устойчивость.
- Нет достоверной статистики всех 30+ видов спорта сразу: каждый входит в исследовательский каталог, но для прогноза нужны конкретные данные и контроль рынка. Составы игроков сейчас не подтверждены.
- Текущая V7 не включает автоматические платные вызовы LLM для чтения статей: ключей нет, стоимость и права на использование источников не согласованы. Без ключей AI-карточка честно сообщает `NOT_CONFIGURED`.
- Старые списки гипотез моделей могут содержать противоположные исходы; **основной портфель** — не более одного исхода на матч. Нельзя суммировать все гипотезы как реальные ставки.
- Код протестирован локально, но реальную работу на VPS, текущую схему Docker/HTML старого центра и доступность внешних серверов подтверждает только твой успешный `apply` + `once` + диагностика.
