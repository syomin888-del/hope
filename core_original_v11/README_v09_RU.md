# ORACLE CORE v0.9 — Autonomous Scientific Memory

**Состояние:** обновление реального ORACLE v0.7. Новые модули `knowledge.py` и `discovery.py` плюс два плановых задания в `brain_daemon.py`. Сборщики, крипто-ML, веб-панель, безопасный виртуальный режим и прежние тесты сохранены. Ни гарантированной точности, ни готовых выгодных ставок, ни реальных покупок нет.

## Что улучшено по-настоящему

1. **Память наблюдений** `knowledge.py`: бережно выделяет избранные структурированные поля из исходных снимков, проверяет SHA-256, сохраняет ID исходного документа, время наблюдения и время, заявленное источником. Сведения *не становятся* независимым доказательством только от хранения. Несовместимые записи и подменённые хэши отклоняются.
2. **Машина времени**: `as_known(c, ISO_TIMESTAMP, provider, subject)` восстанавливает **только то, что система реально получила к моменту запроса**; опубликованная задним числом дата не позволяет искусственно знать событие заранее.
3. **Автономная лаборатория гипотез** `discovery.py`: заранее заданные базовые правила и автоматически скомпонованные пары условий о криптодвижениях/объёмах, проверяемые для BTC/ETH/SOL на сроках 6 и 24 часа. Обучающий, проверочный и контрольный периоды разделяются по времени; на границах есть зазор, исходы не перекрываются. Правила фиксируются в журнале до обработки данных.
4. **Штраф за множественные проверки**: правило Бонферрони по заданным гипотезам/горизонтам, интервалы Уилсона, минимальное количество наблюдений. Результаты являются лишь исследовательскими кандидатами. При повторном анализе схожей истории пометка `RETESTED`, повтор **не считается новым независимым доказательством**.
5. **Автономное расписание**: раз в час добавление знаний, ежедневно — проверка гипотез. Никаких финансовых транзакций и платных API.
6. **Веб-панель**: добавлены число сохранённых наблюдений, исследования и журнал последних экспериментов.

**Ограничения:** не подключены языковые ИИ; новости сохраняются как исходные события, не все статьи автоматически осмыслены. Исследование причинности и прогнозирование спорта на пользовательском уровне ещё не реализованы. Статистические эвристики не означают прибыльную стратегию; оценка коррелированных рыночных наблюдений остаётся приближённой. Разработку и реальные API необходимо проверять на пользовательской машине.

## Если ORACLE ещё не установлен

Установите Python 3.10+ и запустите из распакованной папки:

```bash
cd ~/Downloads/ORACLE_CORE_v09
bash install_mac.sh
```

Откройте `http://localhost:8765/#intelligence` на Mac. Для начала без ожидания расписания:

```bash
./.venv/bin/python knowledge.py ingest
./.venv/bin/python discovery.py run
./.venv/bin/python brain_daemon.py status
```

Исторические свечи будут постепенно загружаться прежним планировщиком. Если данных недостаточно, лаборатория скажет `WAIT_DATA`; это нормально. Компьютер должен оставаться включённым и не спать.

## Обновление установленного v0.7, не теряя базу

Останови старый экземпляр **в его папке**:

```bash
cd ~/Downloads/ORACLE_CORE_v07
bash uninstall_mac.sh
```

Распакуй новый архив рядом со старой папкой. Перенеси базу с сохранением исходного экземпляра:

```bash
cd ~/Downloads/ORACLE_CORE_v09
python3 upgrade_from_v07.py --from ~/Downloads/ORACLE_CORE_v07
bash install_mac.sh
```

Скрипт читает старую базу через режим `ro`, делает проверенный SQLite backup, переносит `.env` с правами 600 и локальные `model_artifacts`. В существующую базу назначения он не пишет. **Не перемещай `.env` в чат и не присылай мне ключи.** Если v0.8 уже была реально установлена, НЕ применяй этот скрипт к неизвестной версии: сначала нужен полный архив/структура её БД, чтобы спроектировать миграцию.

## Сервер без включённого Mac

Docker Compose из v0.7 сохранён и запускает источник, интеллект и веб-панель. Нужен Linux-сервер с Docker, доступом к соответствующим источникам и диском для архива. **Не публикуй локальную панель в интернет напрямую.** Компьютерное время и хранилище не бесплатны сами по себе; этот пакет не покупает сервер и не выполняет удалённое развёртывание.

## Технические границы

- 100% точного знания будущего нет. Уровень анализа не должен измеряться числом «агентов» или записей без оценки предсказаний на будущих исходах.
- Гипотезы из `discovery.py` — ограниченная грамматика наблюдаемых правил и их сочетаний, а не свободное изобретательство ИИ; это контролируемый первый шаг. Убедительное исследование требует зафиксировать гипотезу и получить новые независимые данные после её создания.
- Хеш проверяет целостность относительно сохранённого содержимого, но не доказательную силу или истинность исходного источника.
- Прогнозировать реальные события и рекомендовать использование денег без независимой калибровки нельзя.
